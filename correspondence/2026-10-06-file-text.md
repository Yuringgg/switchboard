## What happens now

Every saved PDF and audio recording is read by the worker and the result kept
on the file's own `attachments` row:

- **PDFs** — their text, read on the worker with `unpdf` (PDF.js). Nothing
  leaves the worker.
- **Recordings** — transcribed by Groq Whisper (`whisper-large-v3-turbo`), the
  language detected rather than pinned to English. A 12 MB m4a is minutes long;
  the 84 KB test clip came back in 0.8 s, Tagalog numbers included.
- **Pictures** — not read. Needs a vision model; deferred by Yuri.

**Future files too.** The reader runs right after the file sweep in the same
2-minute loop (`apps/worker/src/index.ts`), on every file whose `text_status`
is null — so a file is read within a couple of minutes of being saved, and the
17 that existed before drain three a pass (about twelve minutes).

The Files page shows a folded **Transcript** / **What it says** under each read
file (the first ~400 characters, `text_preview`). Uriel gets the whole thing
through a new tool, **`read_file`**; every `files` entry now carries a
`fileId` and `readable: true` once it has been read, and `get_files` matches
words inside files as well as their names.

⚠ Safety rails: one file at a time, three per pass, PDFs over 8 MB not parsed
(the worker has 1 GiB — the 2026-09-27 OOM); a rate limit stops the pass and
writes nothing, so the file is retried; logs carry file ids, never names or
text; `read_file` filters `owner_id` by hand (checked live — the other tenant
gets "That file is not in your Switchboard").
